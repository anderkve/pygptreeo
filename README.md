## Introduction
pyGPTreeO is a Python tool designed for online/continual regression tasks. It implements a dynamically growing tree where each leaf node is a local Gaussian Process (GP) regressor. This structure makes it particularly well-suited for learning from data streams where data points arrive sequentially. It builds on the DLGP approach by Lederer et al (https://arxiv.org/abs/2006.09446) and our R package [GPTreeO](https://cran.r-project.org/web/packages/GPTreeO/index.html) (https://arxiv.org/abs/2410.01024).

## How it works (briefly)
- Using the sequential input stream, GPTreeO dynamically constructs a binary tree where each node represents a specific region of the input space.
- Leaf nodes contain their own Gaussian Process (GP) model, which is trained on the data points that fall into that node's defined region.
- When a leaf node accumulates a sufficient number of data points (determined by the `Nbar` parameter), it splits into two children. This process creates more specialized models for subregions of the data space.
- Predictions are typically made by the GP model in the leaf node into which a new data point falls. For overlapping regions (controlled by the `theta` parameter), predictions can be an aggregate prediction from multiple relevant GPs.

Interfaces to several established GP packages already exist, and the code can easily be extended with more.

## Usage example
Here's a simple example of how to use GPTreeO:

```python
import numpy as np
from pygptreeo import GPTree

# 1. Initialize GPTree
# Nbar is the maximum number of points per leaf before it considers splitting.
# The leaf GPs are the default scikit-learn GPs; pass GPR=... to use your own.
gpt = GPTree(Nbar=50)

# 2. Prepare some data
# Let's create some 1D data for simplicity
X_train = np.linspace(0, 10, 100).reshape(-1, 1)
y_train = np.sin(X_train).ravel().reshape(-1, 1)

# 3. Feed data points to the tree sequentially
print("Training the GPTree...")
sigma = 1e-3  # observation noise (standard deviation) for each point
for i in range(len(X_train)):
    # GPTree expects 2D input for X and y for a single sample
    x_sample = X_train[i:i+1, :]
    y_sample = y_train[i:i+1, :]
    # update_tree(x, y, sigma): sigma is the observation-noise std for this point
    gpt.update_tree(x_sample, y_sample, sigma)
    if (i + 1) % 20 == 0:
        print(f"Processed {i+1}/{len(X_train)} points.")

# 4. Make predictions
print("\nMaking predictions...")
X_test = np.array([[0.5], [2.5], [5.5], [7.5], [9.5]])
y_pred, y_std = gpt.predict(X_test)

for i in range(len(X_test)):
    print(f"Input: {X_test[i,0]}, Prediction: {y_pred[i,0]:.4f}, StdDev: {y_std[i,0]:.4f}")

# The tree structure can be printed (optional, can be very large for many points)
# print("\nGPTree structure:")
# print(gpt.root)
```

## Adding many points at once

`update_tree` takes a single data point. A set of data points can be passed to `batch_update_tree`, which adds them to the tree one by one in the same way:

```python
gpt.batch_update_tree(X_train, y_train, sigma_train)   # arrays of shape (N, d), (N,) and (N,)
```

For a tree without data points there is also `fit`, which first builds the tree from all the data points and then trains each leaf GP once:

```python
gpt = GPTree(Nbar=50)
gpt.fit(X_train, y_train, sigma_train)
```

This is faster, by a factor of about 2.5 for 5000 points in our tests, with a similar accuracy. However, the uncertainty calibration is based on the predictions made for each point before it is added to the tree, so after `fit` the predicted uncertainties are the uncalibrated GP uncertainties. They become calibrated as further points are added with `update_tree` or `batch_update_tree`. `fit` raises an error for a tree that already holds data points.

## Selecting a leaf kernel

By default each leaf GP uses an anisotropic Matérn kernel, `ConstantKernel() * Matern(nu=1.5)`, with one length scale per input dimension. The fitted length scales also determine the split dimension: with the default setting `split_dimension_criteria='min_lengthscale'` a leaf is split along the dimension with the smallest length scale, i.e. the dimension along which the target function varies fastest. For kernels without per-dimension length scales the dimension with the largest spread in the data points is used instead.

For many target functions `AdditiveMaternKernel` is a better choice. It combines the Matérn kernel with a low-order additive kernel, which models the target as a sum of main effects (`order=1`), or of main effects and pairwise interactions (`order=2`).

```python
from pygptreeo import GPTree, Default_GPR, AdditiveMaternKernel

d = 4  # input dimensionality
kernel = AdditiveMaternKernel(d=d, order=2, nu=1.5)
gpt = GPTree(GPR=Default_GPR(kernel=kernel, alpha=1e-6), Nbar=100)
```

The additive component only has `d` length scales and one variance per interaction order, so it requires fewer data points when the target has (approximately) this structure. The Matérn component captures the remaining, non-additive variation. So even when the target has no additive structure there is typically little harm in using `AdditiveMaternKernel`, except for the increased run time from fitting more hyperparameters. The hyperparameters are tuned per leaf by marginal-likelihood maximisation.

Any other scikit-learn kernel can be used in the same way, e.g. `ConstantKernel() * (Matern(nu=1.5, length_scale=[1.0] * d) + RBF(length_scale=[1.0] * d))` as a simpler and computationally cheaper alternative. For periodic inputs there is also `AdditivePeriodicMaternKernel(d=d)`, which is typically only beneficial when several oscillation periods fall within a single leaf.

## Multi-output targets

pyGPTreeO also supports multi-output targets. Set `n_outputs=p` and pass `y` and `sigma` as arrays with `p` columns. The `output_model` option determines how the outputs are modelled within each leaf:

- `'independent'` (default): One GP per output, each with its own kernel hyperparameters.
- `'shared'`: One GP with a single kernel shared by all outputs. This requires one Cholesky factorisation per leaf instead of `p`, and the time of a fit hardly depends on `p`. The accuracy is similar when the outputs have similar length scales. This option is only available with the scikit-learn interface.
- `'pca'`: The tree learns a global linear basis for the output space, using PCA on a subsample of the input stream, and each leaf models the leading principal components with one GP each. Predictions and uncertainties are transformed back to the output space. This is suitable for strongly correlated outputs, e.g. a function `f(t; x)` evaluated on a grid in `t`. By default only the components with a variance above the observation noise level (given by `sigma`) are kept. The number of components can also be set explicitly with `output_basis_components`.
- `'aligned'`: For outputs that are a curve on a grid, given in the order of the grid, with features whose position depends on the inputs: a resonance peak, a kinematic edge, the phase of an oscillation. A prediction is a weighted combination of the curves in a leaf, and a combination of curves with a peak at different positions has several smaller peaks instead of one in between. This option works as `'shared'`, but each leaf also learns how to stretch and compress the grid of each of its curves, depending on the inputs, so that the features of the curves lie on top of each other. It fits its GP to these aligned curves and applies the reverse transformation to its predictions. A leaf only keeps the alignment if it lowers the leave-one-out error of its curves, so for curves without such features the predictions are those of `'shared'`. This option is only available with the scikit-learn interface.

```python
gpt = GPTree(Nbar=100, n_outputs=100, output_model='aligned')
for x, y, sigma in data_stream:               # y and sigma have shape (1, 100)
    y_pred, y_std = gpt.predict(x)
    gpt.update_tree(x, y, sigma)
```

A typical multi-output target is a function `f(t; x)` evaluated on a grid in `t`, e.g. a spectrum or a differential cross-section that depends on the model parameters `x`. Some recommendations for such targets, from our tests on twelve families of physics-like curves:

- `'shared'` reaches the accuracy of `'independent'` (within a factor 2) at a small fraction of the run time, and is a good first choice. For curves with a feature that moves with the inputs, `'aligned'` lowered the error by a factor 1.6 to 12 (3.6 to 3.9 for a resonance peak), at two to three times the run time of `'shared'`.
- For curves that change smoothly with a few inputs, a smoother leaf kernel than the default is the simplest improvement: with `GPR=Default_GPR(nu=2.5)` (Matérn 5/2) the error was 3 times lower in the geometric mean over our twelve families, and up to 58 times lower for a single family, at no cost. An RBF kernel was better still for some families, but failed for curves with a sharp peak. Peaks and kinks along the grid do not matter for this choice, as long as they do not move with the inputs.
- A quantity that varies over orders of magnitude should be given as its logarithm, with `sigma` as the uncertainty of the logarithm. For a spectrum over ten decades this lowered the relative error by one to three orders of magnitude, depending on the output model.
- If the position of a feature is known as a function of the inputs, e.g. a resonance at a mass `M` that is one of the parameters, the simplest remedy is a grid relative to that position (in `m / M`), on which the feature no longer moves. For a spectrum with such a peak this lowered the error of `'shared'` by a factor 7, and for a kinematic endpoint by a factor 13, which is what `'aligned'` reached on the fixed grid without that knowledge.
- For `'aligned'` the grid has to resolve the feature that moves, with at least two to three grid points across a peak or an edge. A finer grid costs little, since the time of a fit hardly depends on the number of grid points.
- The global models (see below) also take a curve as their target, and the leaves then model the residual curves. For curves that are smooth in the inputs the additive GP should get a smoother kernel as well (`global_mean_kwargs=dict(nu=2.5)`). On top of Matérn 5/2 leaves it then lowered the error by a factor 1.3 in the geometric mean, and by far more where the curves have a low-order additive structure in the inputs (a factor 40 for an EFT distribution that is quadratic in six Wilson coefficients). It does not help with a sharp feature that moves. With `output_model='aligned'` a leaf that aligns its curves models them directly, and only the other leaves use the global model, so the two can be combined:

```python
gpt = GPTree(GPR=Default_GPR(nu=2.5), Nbar=100, n_outputs=100, output_model='aligned',
             global_mean='additive_gp', global_mean_kwargs=dict(nu=2.5))
```

With this configuration the error was 1.1 to 110 times lower than with the default `'shared'` leaves on our twelve families, and 5.3 times lower in the geometric mean. Without the global model the factor was 4.0, and with `'shared'` leaves and the Matérn 5/2 kernel alone it was 3.1.

See `examples/multioutput_physics_curves.py` for a comparison of the output models on these curve families, and `examples/multioutput_function_learning_pca.py` for the `'pca'` model compared with a B-spline representation of the curves. The benchmark results are given in [`docs/benchmarks.md`](docs/benchmarks.md), section 9.

## Global models (optional)

By default each leaf GP models the target function directly. For high-dimensional targets this becomes inefficient, since the `Nbar` data points in a leaf are not sufficient to constrain a GP with one length scale per input dimension. For such cases pyGPTreeO can maintain a single global model, trained on data from the entire input space, and let the leaf GPs model the residual between the target and the global model prediction. Away from its own training points a leaf GP then reverts to the global model rather than to a constant mean. The predicted uncertainties account for both the uncertainty of the leaf GP and an estimate of the error of the global model.

Two global models are available:

```python
# A GP with a low-order additive + Matérn kernel
gpt = GPTree(Nbar=100, global_mean='additive_gp')

# A neural network (requires PyTorch)
gpt = GPTree(Nbar=100, global_mean='net')
```

- `'additive_gp'` is a GP fitted to a space-filling subsample of the data. It is most effective for targets with (approximately) low-order additive structure, for which the prediction error can be reduced by orders of magnitude. For targets without such structure we find a 15-50% lower error in our tests, at 4-11 times the run time.
- `'net'` is a small neural network (an MLP with three hidden layers) trained on the input stream. It is not limited to additive structure, and is in general the better choice for other targets. In our tests with streams of 40 000 points the error was reduced by a factor 4-20 for targets with a large-scale structure that the network can learn, and by 15-20% for rough, oscillating targets. No improvement was seen for targets where the data points were too sparse to resolve the oscillations. The run time increased by 50-60%.

The global model is refitted as more data arrives, in general each time the number of data points has doubled. A refit typically takes 5-10 seconds for the network and 30 seconds or more for the additive GP, and by default the entire refit is performed within a single `update_tree` call. For the network the refit can instead be distributed over the subsequent `update_tree` calls:

```python
gpt = GPTree(Nbar=100, global_mean='net', global_mean_kwargs=dict(steps_per_update=1))
```

Further options can be passed via `global_mean_kwargs`, see the docstrings of `AdditiveGPGlobalMean` and `FeatureNetLearner`. Benchmark results are given in [`docs/benchmarks.md`](docs/benchmarks.md), and the design of the global models is described in more detail in [`docs/design.md`](docs/design.md). See `examples/example_hybrid.py` for a comparison of a tree with and without the neural network.


## Limiting the memory use (optional)

By default the tree keeps every leaf it creates, so its memory use grows with the number of data points. For streams that are too long for this, a memory limit can be set:

```python
gpt = GPTree(Nbar=100, max_memory_mb=500)
```

The tree then keeps its own estimate of its size, available as `gpt.memory_mb`, within the limit. Nothing changes until the limit is reached. From then on the tree does two things:

- It puts leaves to sleep, starting with the leaf that has gone unused for the longest time. A sleeping leaf keeps its data points and its kernel hyperparameters, but releases the Cholesky factor of its GP, which takes most of the memory of a leaf. The factor is computed again when the leaf is next used, so the predictions do not change.
- When putting leaves to sleep is no longer enough, it removes the leaf that has gone longest without receiving a data point, together with its data points and its GP. The leaf's sibling in the tree takes over its region.

## Fitting the leaves in other processes (optional)

Most of the time of an update is spent on optimising the kernel hyperparameters of a leaf. This step can be carried out in other processes, for instance by MPI workers, while one process holds the tree:

```python
from pygptreeo import GPTree, solve_fit_task

gpt = GPTree(Nbar=100)

# In the process that holds the tree
task = gpt.update_tree(x, y, sigma, defer_fits=True)   # a fit task, or None
if task is not None:
    send_to_a_worker(task)
gpt.apply_fit_result(result)                           # for each result that comes back

# In a worker process
result = solve_fit_task(task)
```

With `defer_fits=True` a leaf that is due a fit is not fitted in `update_tree`. The fit is returned as a task: a small dictionary that can be pickled, with the data points of the leaf. `solve_fit_task` optimises the hyperparameters and returns them, and `apply_fit_result` refits the leaf with these hyperparameters to the data points that it holds by then. Until the result is applied the leaf keeps its previous hyperparameters, and new data points are added to its GP as usual. For a set of data points, `batch_update_tree(X, y, sigma, defer_fits=True)` returns the list of tasks.

pyGPTreeO only creates the tasks and applies the results. Sending them between processes is left to the user. `examples/mpi_fit_workers.py` is a complete example with `mpi4py`, in which the process that holds the tree handled around three times as many data points per second with fit workers. Note that this option requires the scikit-learn interface and, for multi-output targets, `output_model='independent'`. Otherwise the leaves are fitted in `update_tree` as before.

## Using GPyTorch

By default the leaf GPs are scikit-learn GP regressors. GPyTorch can be used instead via the `GPyTorchAdapter`:

```python
import gpytorch
from pygptreeo import GPTree
from pygptreeo.adapters import GPyTorchAdapter

adapter = GPyTorchAdapter(
    mean_module=gpytorch.means.ConstantMean(),
    covar_module=gpytorch.kernels.ScaleKernel(gpytorch.kernels.MaternKernel(nu=1.5, ard_num_dims=d)),
    optimizer='adam', learning_rate=0.1, training_iterations=50, device='cpu')
gpt = GPTree(GPR=adapter, Nbar=100)
```

The hyperparameters of each leaf GP are optimised with `training_iterations` steps of the chosen optimizer (`'adam'` or `'lbfgs'`), and `device='cuda'` enables GPU computation. Note that `output_model='shared'` and the `'min_lengthscale'` split criterion currently require the scikit-learn interface. With GPyTorch the leaves are instead split along the dimension with the largest spread in the data points. See `examples/gpytorch_backend.py` for a comparison of the two interfaces.
