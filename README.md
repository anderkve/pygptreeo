## Introduction
pyGPTreeO is a Python tool designed for online/continual regression tasks. It implements a dynamically growing tree where each leaf node is a local Gaussian Process (GP) regressor. This structure makes it particularly well-suited for learning from data streams where data points arrive sequentially. It builds on the DLGP approach by Lederer et al (https://arxiv.org/abs/2006.09446) and our R package [GPTreeO](https://cran.r-project.org/web/packages/GPTreeO/index.html) (https://arxiv.org/abs/2410.01024).

## How it works (briefly)
- Using the sequential input stream, GPTreeO dynamically constructs a binary tree where each node represents a specific region of the input space.
- Leaf nodes contain their own Gaussian Process (GP) model, which is trained on the data points that fall into that node's defined region.
- When a leaf node accumulates a sufficient number of data points (determined by the `Nbar` parameter), it splits into two children. This process creates more specialized models for subregions of the data space.
- Predictions are typically made by the GP model in the leaf node into which a new data point falls. For overlapping regions (controlled by the `theta` parameter) or when using `GPForest`, predictions can be an aggregate prediction from multiple relevant GPs.

Interfaces to several established GP packages already exist, and the code can easily be extended with more.

## Usage example
Here's a simple example of how to use GPTreeO:

```python
import numpy as np
from pygptreeo import GPTree

# 1. Initialize GPTree
# Nbar is the maximum number of points per leaf before it considers splitting.
# The leaf GPs are the default scikit-learn GPs; pass GPR=... to use your own.
gpt = GPTree(Nbar=50)

# 2. Prepare some data
# Let's create some 1D data for simplicity
X_train = np.linspace(0, 10, 100).reshape(-1, 1)
y_train = np.sin(X_train).ravel().reshape(-1, 1)

# 3. Feed data points to the tree sequentially
print("Training the GPTree...")
sigma = 1e-3  # observation noise (standard deviation) for each point
for i in range(len(X_train)):
    # GPTree expects 2D input for X and y for a single sample
    x_sample = X_train[i:i+1, :]
    y_sample = y_train[i:i+1, :]
    # update_tree(x, y, sigma): sigma is the observation-noise std for this point
    gpt.update_tree(x_sample, y_sample, sigma)
    if (i + 1) % 20 == 0:
        print(f"Processed {i+1}/{len(X_train)} points.")

# 4. Make predictions
print("\nMaking predictions...")
X_test = np.array([[0.5], [2.5], [5.5], [7.5], [9.5]])
y_pred, y_std = gpt.predict(X_test)

for i in range(len(X_test)):
    print(f"Input: {X_test[i,0]}, Prediction: {y_pred[i,0]:.4f}, StdDev: {y_std[i,0]:.4f}")

# The tree structure can be printed (optional, can be very large for many points)
# print("\nGPTree structure:")
# print(gpt.root)
```

## Selecting a leaf kernel

By default each leaf GP uses an anisotropic Matérn kernel, `ConstantKernel() * Matern(nu=1.5)`, with one length scale per input dimension. These length scales are also used when a leaf is split. With the default setting `split_dimension_criteria='min_lengthscale'` a leaf is split along the dimension with the shortest length scale, i.e. the dimension where the target function varies the fastest. (For kernels without per-dimension length scales the leaf is split along the dimension where its data points are most spread out.)

For many target functions `AdditiveMaternKernel` is a better choice. It adds an additive kernel to the Matérn kernel. In the additive kernel the target is modelled as a sum of functions of single inputs (`order=1`), or of single inputs and pairs of inputs (`order=2`).

```python
from pygptreeo import GPTree, Default_GPR, AdditiveMaternKernel

d = 4  # input dimensionality
kernel = AdditiveMaternKernel(d=d, order=2, nu=1.5)
gpt = GPTree(GPR=Default_GPR(kernel=kernel, alpha=1e-6), Nbar=100)
```

The additive kernel has few hyperparameters, so fewer data points are needed when the target really has this kind of structure. The Matérn kernel takes care of the rest. So even when the target has no additive structure there is typically little harm in using `AdditiveMaternKernel`, except for the increased run time from fitting more hyperparameters. The hyperparameters are tuned per leaf by marginal-likelihood maximisation.

Any other scikit-learn kernel can be used in the same way, e.g. `ConstantKernel() * (Matern(nu=1.5, length_scale=[1.0] * d) + RBF(length_scale=[1.0] * d))` as a simpler and cheaper alternative. For periodic inputs there is also `AdditivePeriodicMaternKernel(d=d)`, but this is typically only useful when a single leaf covers several periods.

## Multi-output targets

pyGPTreeO can also learn target functions with several outputs. Set `n_outputs=p` and pass `y` and `sigma` as arrays with `p` columns. The `output_model` setting decides how the outputs are modelled in each leaf:

- `'independent'` (default): One GP per output, each with its own hyperparameters.
- `'shared'`: One GP with the same kernel for all outputs. This is faster, and typically about as accurate when the outputs vary on similar length scales. It requires the scikit-learn interface.
- `'pca'`: The outputs are first transformed using a PCA that is learned from the data, and each leaf then uses one GP per principal component. This is useful when the outputs are strongly correlated, e.g. when they are the values of a function `f(t; x)` on a grid in `t`. By default the number of components is chosen based on the noise level given by `sigma`, but it can also be set with `output_basis_components`.

```python
gpt = GPTree(Nbar=50, n_outputs=100, output_model='pca')
gpt.fit(X_train, Y_train, sigma_train)    # Y_train has shape (N, 100)
Y_pred, Y_std = gpt.predict(X_test)
```

Here the tree is trained on all the data at once with `fit`. Note that the predicted uncertainties are then not calibrated, since the calibration uses the predictions made for each new point in `update_tree`. See `examples/multioutput_function_learning_pca.py` for a comparison of the three options.

## Global models (optional)

By default each leaf GP models the target function directly. This becomes difficult when the target depends on many inputs, since the data points in a single leaf are then too few to learn the function in that region. For such cases pyGPTreeO can fit a single global model to the data from the whole input space, and let the leaf GPs model the difference between the data and the global model. Away from its own data points a leaf then falls back to the global model.

There are two global models to choose from:

```python
# A GP with an additive kernel
gpt = GPTree(Nbar=100, global_mean='additive_gp')

# A neural network (requires PyTorch)
gpt = GPTree(Nbar=100, global_mean='net')
```

- `'additive_gp'` works best when the target is close to a sum of functions of one or two inputs. For such targets the error can be reduced by orders of magnitude. For targets without this structure we see a 15-50% lower error in our tests, but the run time is 4-11 times longer.
- `'net'` is the better choice for most other targets. In our tests with 40 000 input points the error was reduced by a factor 4-20 for targets with some large-scale structure that the network can learn. For rough, oscillating targets the improvement was 15-20%, or none at all when the data points were too sparse to resolve the oscillations. The run time increased by 50-60%.

The global model is refitted now and then as more data comes in. A refit typically takes 5-10 seconds for the network and half a minute or more for the additive GP, and by default this happens inside a single `update_tree` call. For the network the refit can instead be spread out over the following calls:

```python
gpt = GPTree(Nbar=100, global_mean='net', global_mean_kwargs=dict(steps_per_update=1))
```

Other settings for the global models can be passed in the same way, see the docstrings of `AdditiveGPGlobalMean` and `FeatureNetLearner`. The test results are collected in [`docs/benchmarks.md`](docs/benchmarks.md), and [`docs/design.md`](docs/design.md) explains in more detail how the global models work. The script `examples/example_hybrid.py` compares a tree with and without the neural network.

## Using GPyTorch

The leaf GPs use scikit-learn by default. To use GPyTorch instead, pass a `GPyTorchAdapter` to the tree:

```python
import gpytorch
from pygptreeo import GPTree
from pygptreeo.adapters import GPyTorchAdapter

adapter = GPyTorchAdapter(
    mean_module=gpytorch.means.ConstantMean(),
    covar_module=gpytorch.kernels.ScaleKernel(gpytorch.kernels.MaternKernel(nu=1.5, ard_num_dims=d)),
    optimizer='adam', learning_rate=0.1, training_iterations=50, device='cpu')
gpt = GPTree(GPR=adapter, Nbar=100)
```

The hyperparameters in each leaf are fitted with `training_iterations` steps of the chosen optimizer (`'adam'` or `'lbfgs'`). Set `device='cuda'` to run on a GPU. Note that `output_model='shared'` and the `'min_lengthscale'` split criterion are not available with GPyTorch. In the latter case the leaves are split along the dimension where the data points are most spread out. See `examples/gpytorch_backend.py` for a comparison with scikit-learn.
